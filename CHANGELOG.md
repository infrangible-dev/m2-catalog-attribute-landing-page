# Changelog

## 3.0.2

### Changed

- Unit tests: a test helper no longer takes a parameter that every call passes the same value, as PhpStorm reports
  it ("Parameter's value is always"); the behavior of the module is unchanged.

## 3.0.1

### Changed

- Supports PHP 8.1 again, like Magento 2.4.6: the Adobe Commerce Marketplace requires modules to allow every PHP
  version of the Magento versions they support.

## 3.0.0

### Breaking changes

- Requires Magento 2.4.6 or newer and PHP 8.2 or newer. Older versions of Magento and PHP 7.1 to 8.1 are no longer
  supported; use version 2.x for these.
- Requires `infrangible/m2-backend-widget` 4.0, `infrangible/m2-core` 5.0, `infrangible/m2-foundation` 3.0 and
  `fewedev/base` 2.4, and the Magento modules the module uses (also `magento/module-elasticsearch`, whose search
  classes the product list of the landing pages uses with OpenSearch and Elasticsearch).
- The tables are declared in `db_schema.xml`; the class `InstallSchema` is removed. Existing tables are updated.
- All classes have native types, and the constructors use constructor property promotion. The constructors of the
  helpers, controllers, blocks and models changed.
- The views implement `HttpGetActionInterface` instead of extending Magento's deprecated `Action`.
- The models have typed getters (`getAttributeId()`, `getValue()`, `getStoreIds()`, `getCmsBlockId()`, …) instead of
  the magic getters of the numbered fields; `getPageTitle()` returns the headline if no title is set.
- `addStoreFilter()` of the collections takes a store ID, `addActiveFilter()` returns the collection.
- The unused field "Check Active" of pages is removed, its column is dropped.
- Removed classes: `Model\ResourceModel\Collection` (a virtual type of Magento's search collection),
  `Block\Navigation`, `Block\Navigation\State` and `Block\Product\ProductList\Toolbar` (Magento's blocks),
  `Model\Layer\CollectionFilter`, and the plugin on all product collections that turned "eq" conditions with lists
  into "in".

### Fixed

- Landing pages failed with a fatal error on Magento 2.4.6 and newer: the product collection copied a constructor of
  Magento whose arguments Magento no longer provides.
- The forms of the admin showed no attributes and values since Magento 2.4.7, so saving a page or group removed
  them.
- Inactive landing pages and pages of other store views could be opened with the address of the view.
- Paths without the URL suffix of categories were shortened anyway, so they could show another page.
- A URL key of an inactive page or group could be used again, which collided when the page was activated.
- Landing pages and groups without store views were missing from the grids and could not be edited.
- The image position "Before Headline" showed no image.
- An error while rendering a CMS block of a page or group ended in a type error.
- Groups left out pages with several values of a multiselect attribute; the products of the pages in a group were
  only filtered by the first attribute, and values of multiselect attributes found no products.
- The URLs of images, logos and thumbnails had a double slash.
- Templates escape their output, also the headlines of pages and groups.
- Layout handles contained the values of the attributes unchanged, also spaces and other characters.
- The datetime values had the default `0000-00-00 00:00:00`, which strict SQL modes reject; an empty CMS block of
  a group could not be saved.

### Changed

- The search request of the landing pages is generated by a class of its own instead of a subclass of Magento's
  generator.
- CMS blocks are rendered with Magento's CMS block widget instead of the deprecated `Magento\Cms\Block\Block`.
- The texts are translated into 24 languages.
- Unit tests.
